# 30题质量对照：v2方案

目的：比较同一F16文件量化出的Q8_0与Q4_0，在电路基础任务上的回答质量；不以生成速度替代正确性。

## 固定条件

- 使用 `eval_questions_v2.json` 中30道新题，每类5题。
- 旧A/B/C为开发题，不计入本轮30题。
- 保持 `batch_eval.py` 内已有系统提示词不变；temperature=0、max_tokens=512、关闭思考与输入前缀缓存复用。
- 使用同一台电脑、相同服务槽位/上下文/KV配置，只替换同源量化文件和模型别名；每道题均为独立请求，无聊天历史。
- 每版每题先测一次；记录输出截断情况，不能以正常stop替代正确性判断。
- 参考答案和评分标准只保存到结果记录，不放入发送给模型的messages。
- 每次记录题库SHA-256和服务启动时的/props快照。文件路径不等于模型文件哈希；运行时需另行核对文件来源。

## 类别与评分

| 题号 | 能力 | 数量 |
|---|---|---:|
| O01–O05 | 欧姆定律、毫/微/千/兆单位换算 | 5 |
| P01–P05 | 电功率、能量、平方关系 | 5 |
| N01–N05 | 串并联、多步等效、无负载分压 | 5 |
| C01–C05 | 节点守恒、电容电荷/能量、RC | 5 |
| I01–I05 | 信息不足时能否指出独立的额外条件 | 5 |
| F01–F05 | 能否纠正错误前提与矛盾数据 | 5 |

按每题预先写好的pass_rule做语义复核，正确等价单位可接受；最终数值正确但推导存在实质错误不能通过。信息不足题不允许自行编造条件；“缺少所求未知量”不算指出可求解的额外条件。输出被截断则保留length标志并判为本轮未通过，避免事后选择性放宽某一模型的输出上限。

自动程序负责发送与留档，不用“答案包含某个数字”自动认定正确。逐题记录通过/未通过及理由，汇总总分、各类得分、截断数，以及同一道题两版的差异。人工复核允许保留“需要复查”的状态，在复查前不强行给总分。

## 运行

先以相同配置启动Q8服务：

```powershell
llama-server --model "models\Qwen3-0.6B-local-Q8_0.gguf" --device Vulkan0 --gpu-layers 99 --ctx-size 8192 --parallel 2 --cache-type-k q8_0 --cache-type-v q8_0 --host 127.0.0.1 --port 8080 --alias qwen-local-q8
.\.venv\Scripts\python.exe batch_eval.py qwen-local-q8 --questions eval_questions_v2.json --max-tokens 512
```

等客户端完成，在服务窗口按Ctrl+C停止旧服务。将模型路径改为`models\Qwen3-0.6B-local-Q4_0.gguf`，别名改为`qwen-local-q4`，其余参数保持一致；再次运行客户端：

```powershell
.\.venv\Scripts\python.exe batch_eval.py qwen-local-q4 --questions eval_questions_v2.json --max-tokens 512
```

服务若绑定局域网IPv4，客户端增加`--base-url http://实际地址:8080`。结果保存在`evaluations/run_*.jsonl`，模型权重与原始日志不上传Git。

## 结果的适用范围

这些是新编写、未用于修改当前提示词的本地检查题，不是公认标准测试集；无法保证预训练语料从未出现相似题。大部分数值题较简单，模板相关性较高。不得将30题得分当作总体可靠性或通用模型排名；类别只含5题，单题会使该类得分变化20个百分点。

本轮先固定题库再观察回答。若看到错误后修改提示词，后续结果需作为新配置记录，另用未参与修改的新题验证，不能覆盖本轮基线。
