# 把数值计算交给程序：第一步

提示词对照未在12道新题上提高通过数，因此先制作一个独立、可审阅的计算模块。它尚未接入模型；不会自动理解题目或修正模型错误。

当前只支持两种计算：

- 已知电压与正电阻，计算电流 `I=U/R`；支持ohm、kohm、Mohm。
- 已知恒定非负功率与非负时长，计算消耗电能 `E=Pt`；支持s、min、h。

数值和单位必须明确输入，缺失时由命令行报错，不会默认猜值。使用Python Decimal避免常见二进制浮点显示误差；除法有28位有效十进制精度限制，并不代表物理测量无限精确。它只验证输入形式和有限的取值范围，不能识别输入是否忠实对应真实电路。

在项目目录运行：

```powershell
.\.venv\Scripts\python.exe circuit_calculator.py current --voltage 9.4 --resistance 4.7 --resistance-unit kohm
.\.venv\Scripts\python.exe circuit_calculator.py energy --power 2 --duration 3 --time-unit min
```

第一条会显示标准化输入为4700 Ω，结果0.002 A、2 mA；第二条显示180秒、360 J。单位换算和最终结果都保留在JSON里，便于追溯。

## 接入模型：结构化提取与限定调用

新增`ask_with_calculator.py`。模型服务的JSON Schema约束保证输出符合限定结构，客户端再校验操作、字段、单位、数值及原文引用，然后只调用固定Python函数。不会执行模型生成的代码、公式字符串或系统命令。

```powershell
.\.venv\Scripts\python.exe ask_with_calculator.py http://127.0.0.1:8080 --model qwen-local-q4
```

若服务监听局域网地址，将上面的URL替换为实际服务地址。输入题目后会显示模型提取的单位参数、程序判定及计算结果。模型的`message`属于未经验证的备注，默认不显示；仅在`--debug`时显示，且仍不会被当作计算答案。计算成功后的最终数值直接由Python输出，不再交给模型改写。所有请求与结果单独保存在本地`evaluations/calculator_*.json`。

当前仅支持单电阻、伏特电压、瓦特功率及所列电阻/时间单位；不支持电阻网络、交流阻抗、缺失单位、汉字数字等泛化输入。相关题目若文本出现多组同类量，客户端保守拒绝，需先把目标电路和目标量说清楚。未支持或提取结构/引用不合格时会拒绝计算，拒绝并不等同于证明题目条件不足。

## 开发样例验证

这些是已观察过的开发例子，不是未见题质量评测：

| 题目 | 程序行为 |
|---|---|
| 4.7千欧、9.4伏求电流 | 提取正确，转换4700 Ω，结果2 mA |
| 2瓦工作3分钟求电能 | 提取正确，转换180秒，结果360 J；模型message却写6 J，未采纳此备注 |
| 仅4.7千欧求电流 | 模型将阻值错填为电压，引用仍是千欧；校验器拒绝，没有计算 |

初版只请求普通JSON时出现字段遗漏、提取47000等错误，失败记录保留。随后增加更明确的引用格式说明及JSON Schema，属于开发迭代，不能把上述成功样例当作独立成绩。

当前离线测试覆盖单位/数值错配、候选量歧义和无效/不完整模型响应。新增的对象分句守卫能拦截“设备A有功率、设备B有时长”这类显式交叉归属，并允许相邻分句都明确指向设备A。它是有边界的规则：像“甲消耗2瓦，乙运行3分钟”这类未识别的对象别名仍可能漏过。Schema只约束格式，原文匹配不能理解否定或复杂电路条件。即使计算正确，模型选错量或操作仍可能给出不适用的答案；不能把校验器通过直接等同于题意理解可靠。
