# 单位检查与独立核验提示词：预先固定的实验方案

## 要回答的问题

在同一Q4模型上，添加两类通用提醒（统一单位、独立核验用户说法并检查自洽性）能否改善回答？不训练或替换权重，不向模型提供参考答案。

## 固定后再测

1. `baseline`为已有SYSTEM_PROMPT；`checked`在其后追加统一单位制、独立核验、检查数值单位推导结论一致的规则。默认仍是baseline，旧程序行为不变。
2. 30道v2题已被观察，作为回归/开发集，不再视作新题。对照原Q4基线日志，保留原始成绩和截断，不覆盖旧记录。
3. `eval_questions_holdout_v1.json`的12题在看到新提示词输出前固定，baseline与checked各运行一次。四题单位、四题错误前提、四题条件充分性；后四题成对包含充分与不足条件，检查是否过度拒答。
4. 题库和提示词均记录SHA-256。模型保持local-Q4_0、两个槽位、每槽位上下文4096、Q8_0 KV；temperature=0、max_tokens=512、禁用思考和输入前缀复用。
5. 判分沿用预设规则：数值、单位、推导与结论无实质错误才通过；错误前提必须纠正，条件不足需指出独立额外条件；截断未通过。逐条语义审阅，允许用户复查。
6. 对30题同时报告修复题和退步题；对新12题报告配对得分与逐题差异。不根据本轮输出改题、规则或提示词，失败结果也保留。

## 范围

这12题是同领域、与开发题形式接近的新数值/新提问，不是公开标准基准，也不是独立团队出的盲测。题库设计和评分都由Codex提供，每题各一次；不保证预训练语料无类似题。不把提示词引导提升称为模型内在能力或总体可靠性提升。旧30题的原基线与回归发生在不同时间，可能有运行状态差异；12题两版将按顺序在同一服务上测量，但也没有随机化顺序。

## 复现

```powershell
python batch_eval.py qwen-local-q4 --questions eval_questions_v2.json --max-tokens 512 --prompt-version checked
python batch_eval.py qwen-local-q4 --questions eval_questions_holdout_v1.json --max-tokens 512 --prompt-version baseline
python batch_eval.py qwen-local-q4 --questions eval_questions_holdout_v1.json --max-tokens 512 --prompt-version checked
```

局域网服务增加`--base-url http://实际地址:8080`。全部参考答案留在本地评分记录，不进入请求messages。

## 首轮结果

按既定规则由Codex逐条语义复核，供用户复查。[逐题评分与来源](results/prompt_checked_q4_review.json)保留所有失败与退步理由。

| 数据 | 旧baseline | 新checked |
|---|---:|---:|
| 已观察的30道回归题 | 11/30 | 14/30 |
| 运行前固定的12道新题 | 5/12 | 5/12 |
| 新12题中的输出截断 | 0 | 1 |

回归集中修复5题（P04、N04、C05、I03、F04），退步2题（O02、C03）。新题两版通过的是同样5题（H01、H03、H04、H09、H12），没有新题由失败变通过；H10的新回答重复计算、在512 token处截断，旧版也是错误答案，因此总分没有体现这种失败方式的变化。

典型现象：新提示词可让P04显式把3分钟换为180秒并算出360 J，但O02原来正确的0.015×220=3.3 V变成33 V。H02虽然将5 mA正确换为0.005 A，却把平方算错，仍不能得到正确功率。F05甚至写出了4P，结论却继续赞同2倍。提示它检查不等于它能可靠完成检查。

结论：该提示词在观察过的题目上有局部改善和回归，在本轮新题上未观察到完整通过数提升，因此不把checked替换成默认，也不声称整体能力提高。两次截断差异、单次运行及模型辅助评分等限制保留；没有训练模型权重。

如果继续改进，可另做“模型给出计算步骤、确定性程序执行数值与单位计算”的小实验；仅加提示词还没有形成可靠的数值校验机制。本轮12题已经被观察，下一次修改后它们也属于开发/回归数据，不再当作未见题使用。
